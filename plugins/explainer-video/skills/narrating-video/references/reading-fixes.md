## 直し方の選び方

| 直し方 | 書く場所 | 向いているもの | 作り直す音声 |
| --- | --- | --- | --- |
| 置き換え（文字列） | `script.ts` の `READINGS` | その動画で、どこでも同じ読みの語（`DoS` → `ドス`） | その語を含む文だけ |
| 置き換え（正規表現） | `script.ts` の `READING_RULES` | 前後の文字で読みが変わる語（「値」は前が漢字でなければ「あたい」） | 当たった文だけ |
| 読み方で書く | そのステップの `say` | その文だけの読み（IP アドレス、記号の並び） | その文だけ |
| 共通の置き換え | `scripts/reading.ts` | どの動画にも効く書き方（`〜` → から、`p.5` → 5ページ） | 当たった文すべて（全部の動画） |
| ユーザー辞書 | `script.ts` の `USER_DICT` | 置き換えではうまく読めない語（カタカナで書いても切れ目が崩れる語） | その動画の全部の音声 |

- 置き換えの読みは、カタカナかひらがなで書く。英字のままの部分は、エンジンが英字として読む
- `USER_DICT` の形は `[表記, 読み（カタカナ）, アクセント核の位置]`。アクセント核の位置は、読みのモーラ（拍）の何番目で音が下がるか（0 は平板）。分からなければ 0 から試す
- 辞書はエンジンの中で共有される。`voice.ts` は同じ表記の語を消して登録し直すので、別の動画が違う読みで登録すると、後から走った方が効く（manifest のハッシュは自分の辞書しか見ないので気付きにくい）。同じ表記は全動画で同じ読みとアクセントにする

## かなの記法

`out/voice-kana-<slug>.txt` は、1 件 2 行。1 行目がエンジンに渡した文（置き換えの後）、2 行目がエンジンの読み（実際のファイルは、ファイル名の後と 2 行目の頭がタブ）。

```txt
what-1.wav  この短いあたいがハッシュ値です。シャー256なら、いつも256ビットです。
    コノ'/ミジカ'イ/アタイガ'/ハッ_シュチ'デ_ス、シャ'ア/ニヒャク'/ゴジュウ'/ロク'ナラ、…
```

- `/` はアクセント句の切れ目、`、` は間（ポーズ）、`'` はアクセント核（その直後で音が下がる）、`_` は無声化
- 長音は「オ」「エ」で書かれる（「ケエサン」= けいさん、「コオカイ」= こうかい）。これは読み違いではない

## 英字の語

- 略語の多く（PC・OS・DNS・TCP・HTTP・Web・ID・CVSS・DMZ など）は、英字のままで正しく読む。カタカナに置き換えるとかえって崩れる（「ピーシー」→ ピイスィイ）。まず英字のまま作り、崩れたものだけを直す
- 単語として読む略語は崩れやすい。例: LDAP（エルダップ）・OAuth（オーオース）・IdP（アイディーピー）・PKCE（ピクシー）・CSRF（シーサーフ）・JSON（ジェイソン）・RADIUS（ラディウス）・CNAME（シーネーム）。ユーザー辞書か `READINGS` で直す
- 大文字と小文字が混じる語も崩れやすい。例: DoS（ドゥーエスと読む → `READINGS` で「ドス」）・DoH・DRDoS
- ハイフンを含む語は辞書に載らず、後ろの数字を 1 字ずつ読むことがある。例: `SHA-256`（エスエイチエイ、ニイゴオロク）→ `READINGS` で「シャー256」。`T-ID` のような語は `READINGS` で `TID` に置き換えてから、`TID` を辞書に登録する
- 辞書に登録しても、続く助詞によって効かない語がある（「MACアドレス」では効くが「MACが」では戻る）。そのときは `READINGS` でカタカナに置き換える
- ドメイン名・URL は `READINGS` で読み方に置き換え、区切りは読点で書く（`example.co.jp` → 「イグザンプル、ドット、シーオー、ドット、ジェーピー」）。空白で区切っても、共通の置き換えが日本語の前後の空白を取るので、続けて読まれる

## 数字・記号

- IP アドレスは「192.168.20.0/24」のままだと崩れる。`say` で「192、168、20、0、スラッシュ24」と読点で区切る
- 図の記号のひらがな（い・う・き・く など）を続けて読ませると、単語に聞こえる（「いとう」→ 伊藤）。`say` で「い、う」のように読点で区切り、「と」でつながない
- RFC の MUST・SHOULD・MAY は英字のまま読ませず、`say` に「必須」「すべきである」「してもよい」と日本語で書く
- `〜`・`→`・`＝`・`↔`・`p.5`・`図3-2` は、共通の置き換え（`scripts/reading.ts`）が読み方に直す

## 漢字の語

前後の文字で読みが変わるので、`READING_RULES` の正規表現で、間違える形だけを置き換える。

| 語 | 読み違い | 置き換えの例 |
| --- | --- | --- |
| 値 | ネ | 前が漢字・カタカナでないときだけ「あたい」（共通の置き換えに入っている。「数値」「ハッシュ値」は正しく読める） |
| 行（〜の行） | クダリ | `[/(?<![0-9０-９一-鿿])行(?![うえいおわかきくけこっ頭])/g, "ぎょう"]` |
| 語（〜という語） | カタリ | `[/(?<![一-鿿])語(?![一-鿿])/g, "ご"]` |
| 〜る側 | ホノ・ソク | `[/(?<=[ぁ-ん])側/g, "がわ"]`（「送信側」は正しく読める） |
| 本問 | ホントイ | `[/本問(?!題)/g, "ほんもん"]` |
| 出所 | シュッショ | 「出どころ」と書く |
| 親ゾーン・真正性・二役・中分類 | シンゾーン・シンショウセイ・ニヤク・ナカブンルイ | `READINGS` でひらがなに置き換える |
| 送信元 | ソオシン/モト（切れ目が崩れる） | `USER_DICT` に `["送信元", "ソウシンモト", 0]` |

## 空白と区切り

- 日本語の前後の半角の空白は「、」の間として読まれる。共通の置き換えが、日本語と隣り合う空白を取る。英字どうしの間の空白（`LDAP ID`）は残す（詰めると辞書が効かない）
- 読点を入れすぎると、間が多く間延びする。区切りが要るのは、数字の並び・記号の並び・同音の語が続く所
