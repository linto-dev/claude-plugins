## plan.ts

```ts
// 決めたこと（2026-11-29、利用者と決めた）
// - 型: 章立ての解説。各節は 仕組みの図 → 要点
// - 網羅: 原稿の節をすべて入れる（約 40 分の見積もり）
// - 仕上げ: 公開用の MP4 と概要欄まで
// - 話者: 青山龍星（喜び）
// - 図の色: 青 = 注目させる通信、朱 = 攻撃・危険、緑 = 正答・安全
export const VIDEO = {
  slug: "tcpip-ch5",
  title: "IP アドレスとルーティング",
  subtitle: "ネットワーク部・経路表・ICMP",
  source: "出典：著者名『書名』（出版社, 発行年）第5章をもとに作成（図は動画用に描き直し）",
  origin: "../notes/05_ip.md",
  stages: ["問い", "根拠", "考え方", "正答", "ルール"], // 問題の解説の型のときだけ
  notes: ["正答は IPA 公表の解答例に従っています。"],     // 概要欄に足す行（任意）
} as const satisfies VideoMeta;

export const PLAN = [
  { key: "title", chapter: "", title: "表紙", parts: "TitleScene", visual: "題・副題・出典" },
  { key: "addr", chapter: "1｜IP アドレス", title: "ネットワーク部とホスト部", mark: "IP アドレス",
    parts: "自作（アドレスの帯）", visual: "32 ビットの帯を左右に分け、/24 の境目を動かす" },
  // …
] as const satisfies readonly PlanEntry[];
```

- `VIDEO.origin`: 原稿のパス（プロジェクトのルートからの相対パスか、絶対パス）。絵コンテに出るだけで、読み込みはしない
- `key`: 英数字だけ（音声のファイル名・確認用のコンポジションの ID に使う）。問いは `q1`・`q1think`、章ごとに頭をそろえると探しやすい
- `chapter`: 左上の小見出し。章の番号と名前を「1｜IP アドレス」のように書く
- `title`: シーンの見出し（1 行に収まる長さ。全角 24 字まで）
- `mark`: YouTube のチャプター名。章の頭と、問題の解説の各問の「問い」に付ける。最初のシーンは付けなくても 0:00「はじめに」のチャプターになる（付けると名前が変わる）
- `stage`: 右上の段階表示の今の段階（`VIDEO.stages` の名前）。段階の無いシーンでは書かない
- `minSeconds`: 台本の長さより長く見せたいとき（表紙や、動きの長い図）
- `parts`・`visual`: 絵コンテ（STORYBOARD.md）に出る。building-scenes がこれを読んでシーンを書く

## script.ts

```ts
export const SCRIPT: Script<SceneKey> = {
  addr: [
    { caption: "IP アドレスは 32 ビットの数です。" },
    { caption: "前半がネットワーク部、後半がホスト部です。", extra: 0.6 },
    { caption: "192.168.1.0/24 なら、先頭の 24 ビットがネットワーク部です。",
      say: "192、168、1、0、スラッシュ24 なら、先頭の24ビットがネットワーク部です。" },
  ],
};
```

- ステップのフィールド: `caption`（字幕）・`say`（読み上げ。省略で字幕を読む）・`extra`（図の動きに要る追加の秒数）・`hold`（読み終えた後の間の秒数。考える時間は `hold: 5`）
- 表紙のように字幕を出さないステップは `caption: ""` にし、読み上げは `say` に書く
- ステップの尺は自動で決まる: 字幕を読む時間（約 7.5 字/秒）と読み上げの長さの長い方に、前後の間を足す（`src/lib/timing.ts`）。尺を数字で指定しない

## 字幕（caption）の書き方

- 1 ステップは 1〜2 文。字幕は 2 行（約 80 字）までに収める。長いときはステップを分ける
- 画面の図が指しているものを、その順に話す。図に出ていない話を長く続けない
- 話し言葉の「です・ます」で書く。体言止めや箇条書きの文体は図とカードに任せる
- 用語は原稿の表記に合わせ、動画の中で表記を揺らさない（「IP アドレス」と「IPアドレス」を混ぜない）
- 半角の英数字と和文の間には半角の空白を入れる（画面の折り返しは自動で泣き別れを防ぐ）
- 記号（→ ＝ ↔ 〜）は字幕に書いてよい。読み上げでは読み方に置き換わる（`scripts/reading.ts`）
- 原稿の引用は、字幕ではなく `QuoteCard` に出し、字幕では要点を言い換える
- 「ここ」「これ」で図を指すときは、図の側でその場所を強調する

## 読み上げ（say）の書き方

`say` は、字幕のままだと読み違えるときだけ書く。まず字幕のまま音声を作り、読みの点検（narrating-video）で崩れた所だけを直すのが基本。最初から分かっている崩れ方は、次のように書く。

- 英字の略語（PC・DNS・TCP・HTTP など）はカタカナにしない。エンジンはそのまま正しく読むことが多く、カタカナにするとかえって崩れる
- IP アドレスや長い数字の並びは、区切りに読点を入れる（「192、168、1、0、スラッシュ24」）
- 記号のひらがなを続けて読ませない（図の「い」「う」は「い、う」と読点で区切る。「とう」のように単語に聞こえる）
- RFC の MUST・SHOULD などは、日本語（「必須」「すべきである」）で書く
- 読み違えやすい漢字の語（値・行・側 など）は、`READING_RULES` か `say` で直す（reading-fixes.md）

## ステップと図の合わせ方

- 1 つのステップで動かすのは、字幕が指しているものだけ
- 図の要素が出る順は、字幕で触れる順と同じにする
- 図の動きが長い（矢印が伸びる・行が順に出る）ステップは `extra` で秒数を足す（0.5〜1.5 秒）
- 「考える時間」は問いのシーンの最後のステップに `hold: 5` を付ける（カウントダウンが出る）
- 答えを明かすステップと、正答のカードが出るステップを同じにする
