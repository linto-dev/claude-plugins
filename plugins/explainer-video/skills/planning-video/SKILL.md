# 解説動画の企画と台本を作る

引数: `$ARGUMENTS`（原稿のパス。プロジェクトの場所を続けて書いてもよい）

原稿から、シーンの並び（plan.ts）と、字幕と読み上げの文（script.ts）を作る。ここで決めた台本の文の長さと読み上げの長さから、動画の尺が決まる。図の細かい動きは決めない（building-scenes が決める）が、各シーンに何を映すかは plan.ts の `visual` に書く。

プロジェクトのルートで作業する。プロジェクトが無ければ、先に `explainer-video:making-video` でプロジェクトを作る。

## 守ること

- 利用者にしか決められないことは AskUserQuestion で聞き、不明点が無くなるまでやりとりする。推奨の選択肢を先頭に置き、label の末尾に「（推奨）」を付ける。1 回に 4 問まで、答えで中身が変わる問いは次の回に回す
- 台本の事実は、原稿と一次情報（規格・公式の文書・RFC など）で確かめる。原稿にない説明を足すときは、Web Search や context7 で最新の情報を確かめ、出典を参考資料のシーンに載せる
- 原稿の主張を勝手に変えない。原稿の誤りに気付いたら、直し方を利用者に確かめる
- 第三者の著作物は、要約・描き直しにして、本文を長く写さない。出典の表記は plan.ts の `VIDEO.source` に書く

## 手順

```txt
- [ ] 1. 原稿を読む
- [ ] 2. 形を決める
- [ ] 3. 動画のフォルダを作る
- [ ] 4. 計画を書く（plan.ts）
- [ ] 5. 台本を書く（script.ts）
- [ ] 6. 確かめて、了承を得る
```

### 1. 原稿を読む

- 原稿を最後まで読む。長い原稿（目安として 1 ファイル 30KB を超える、または複数のファイル）は、見出しの構成を先に取り出してから、節ごとに読む
- 次を控える: 章と節の構成、図表（何を示すか）、問題・設問の有無、原稿の著作者と出典、原稿の目的（試験対策・入門・社内向けなど）
- 原稿の分量から長さを見積もる。読み上げの文字数 ÷ 6.6 字/秒 に、間と切り替えの分として 1 割を足す。台本の文字数は、原稿の本文の文字数の 3〜5 割になることが多い
- プロジェクトの `src/videos/` にほかの動画があれば、その plan.ts の冒頭のコメント「決めたこと」を読む（シリーズの約束を引き継ぐ）

### 2. 形を決める

[references/formats.md](references/formats.md) を読み、原稿に合う型と分け方の案を作ってから、AskUserQuestion で聞く。聞くことの例（前の会話や plan.ts で決まっていることは聞かない）:

- 1 本にするか、シリーズに分けるか（長さの見積もりを添える。分けるなら、どこで分けるか）
- 型: 章立ての解説・問題の解説・その組み合わせ
- 網羅か要点か: 原稿を削らず全部入れる（長くなる）か、要点に絞る（何分を目安にするか）
- 誰に向けた動画か（前提知識をどこまで説明するか。推奨: 原稿が想定している読者に合わせる）
- どこまで仕上げるか（推奨: 公開用の MP4 と概要欄まで）
- 話者（推奨: VOICEVOX の青山龍星・喜び）。ほかの話者にするなら名前とスタイル
- 見た目を雛形の既定（shadcn/ui の Vega・Neutral）から変えるか（変えるなら DESIGN.md の「見た目を差し替える」）

### 3. 動画のフォルダを作る

- slug（英小文字・数字・ハイフン。コンポジションの ID と音声のフォルダ名になる）を決める。シリーズは同じ頭にそろえる（`tcpip-ch1`・`tcpip-ch2`）
- 見本を写して、Root.tsx に登録する。2 本目からは、同じシリーズの前の動画を `--from` で写すと、部品と書き方を引き継げる

  ```bash
  npm run new-video -- <slug>
  npm run new-video -- <slug> --from <前の動画の slug>
  ```

- 写るのは plan.ts・script.ts（元のまま）と `figures/`。シーンは写らず、`scenes.tsx` は空の `SCENES` になる（全シーンが「作成中」の仮のシーンで動く）。plan.ts と script.ts を書き換えれば、そのまま型の検査が通る

### 4. 計画を書く

`src/videos/<slug>/plan.ts` の `VIDEO` と `PLAN` を書き換える。書き方は [references/script-writing.md](references/script-writing.md) の「plan.ts」。

- 冒頭のコメントに「決めたこと」を書く（型・網羅か要点か・長さの目安・どこまで仕上げるか・話者・図の色の意味・シリーズの約束）。後の工程と、続きをする別の会話がこれを読む
- シーンは「1 シーン = 1 つの図か 1 つの問い」にする。1 シーンのステップは 2〜8 を目安にし、多ければシーンを分ける
- 章の頭のシーンに `mark`（YouTube のチャプター名）を付ける。チャプターは 3 つ以上、各 10 秒以上にする
- 最初のシーン（表紙）には 0:00 のチャプターが自動で付き、名前は「はじめに」になる（表紙に `mark` を付けると名前を変えられる）。表紙から最初の章の頭までが 10 秒に届かないとき（目次を置かない短い動画など）は、最初の章の頭に `mark` を付けず、表紙の `mark` に最初の章の名前を書く
- `visual` には、そのシーンで画面に何が出て、ステップごとに何が動くかを 1〜2 文で書く。原稿の図表を描き直すシーンは「図2（一部改変）」のように元を書く

### 5. 台本を書く

`src/videos/<slug>/script.ts` の `SCRIPT` を、plan.ts のシーンの順に書く。書き方は [references/script-writing.md](references/script-writing.md)。

- 字幕（`caption`）は画面で読む文、読み上げ（`say`）は耳で聞く文。読み方が字幕と同じなら `say` を書かない
- 1 ステップは 1〜2 文、字幕で 2 行（約 80 字）までにする
- 長い動画は `script/` に章ごとのファイルを置き、`script.ts` でまとめる（node から読むので、import には `.ts` を付ける）
- 話者を変えるなら `VOICE` を書く。読みの直し（`READINGS`・`USER_DICT`）は narrating-video で行うので、ここでは書かなくてよい

### 6. 確かめて、了承を得る

- `npx tsc --noEmit` を通す（plan.ts と script.ts のキーの食い違いが型の誤りとして出る）
- 絵コンテを作り、長さを見る。音声がまだ無いので、読み上げの長さを文字数（6.6 字/秒）から見積もった値になる

  ```bash
  npm run storyboard -- <slug>
  ```

- 次を示し、この形で読み上げに進んでよいかを AskUserQuestion で確かめる。直すところがあれば 4・5 に戻る
  - 章立てとシーンの数、長さの見積もり（絵コンテの長さ。読み上げの文字数 ÷ 6.6 字/秒 に間と切り替えを足した値）
  - 決めたこと（plan.ts の冒頭のコメント）
  - 原稿に足した説明と、その出典
  - STORYBOARD.md のパス（利用者が台本を読める）
