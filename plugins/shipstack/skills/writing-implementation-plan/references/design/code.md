# コードの設計の決まり

TypeScript のコードの書き方（型、失敗、ユースケースと依存、入力・出力・DB の行の変換、`packages/fp`、lint と依存の検査）に触れる変更を計画するときに読む。

## 目次

決めること・決めないこと ／ 既存のリポジトリと形が違うとき ／ どこまで関数型にするか ／ 型で業務を表す ／ 日本の業務データ ／ 失敗の扱い ／ ワークフローと依存 ／ 境界 ／ 自前の部品 ／ 依存の向きと機械による検査 ／ 計画に書くこと ／ CLAUDE.md に足す候補 ／ 依頼主に確かめること ／ 確認の問い

## 決めること・決めないこと

- 決める: 型の形、失敗の表し方とエラーの型、ワークフローとポート、境界での検証と変換、DB の行の変換、自前の部品、層ごとの import、lint と依存の検査
- 決めない: 業務ロジックの形の選び方、コンテキストの境界、配置、テナントごとに違う所は領域。並行・重複・障害、互換性、イベントの版、再試行の回数はデータ。テーブルと列はテーブル。テストはテスト。依存の固定は技術の既定値。何から守るかはセキュリティ。処理の単位のイベントは観測

## 既存のリポジトリと形が違うとき

この決まりは、新しいリポジトリと、この形のリポジトリの既定値。`packages/fp` が無い新しいリポジトリでは、最初のフェーズで置く。

- 機能の計画では今のリポジトリの形に合わせる（ORM、class のサービス、neverthrow、`{ ok: boolean }` の Result、`type` や `status` の判別子など）。新しいファイルだけをこの形にしない
- 合わせた所は、計画の README の「決めたこと」に、この決まりとの違いと理由を書く
- 既存の形と食い違わない決まり（判断を純粋関数にする、時刻と ID を引数で受ける、境界で検証する、出口で網羅的に変換する）は、既存の部品のまま当てる
- 移し替えは別の計画にする。`packages/fp` を置く → import を置き換える → 判別子を置き換える、の順にフェーズを分け、1 つの PR で全部を変えない
  - Result: `if (!r.ok)`・`r.isErr()` → `r.kind === "Err"`、`return err(r.error)` → `return r`、`Result.combine` → `Result.all`、`fromPromise` → `Result.tryAsync`、`map` / `andThen` → 早期 return
  - 自前の検証の部品 → `parseWith`。ドメインの中の zod は手書きの `parse` に移す
  - 判別子 → `kind` と PascalCase。公開している API の形式は変えず、境界で写す

## どこまで関数型にするか

既定値は、型で業務を書き、判断を純粋関数にし、失敗を値で返し、I/O を端に寄せる小さな関数型。形は領域の分野で選び、次のように書く。

| 形 | 書き方 |
| --- | --- |
| event sourcing | 純粋な `decide`（コマンド → イベント）と `evolve`。状態と射影は `events.reduce(evolve, …)` |
| domain model | 状態ごとの型、遷移関数、`decideXxx`。I/O はユースケースの前後 |
| active record | 型付きのデータと読み書きの変換関数。純粋な核を作り込まない |
| transaction script | `Promise<Result>` を返す関数 1 つ。状態の型を作り込まない |

- Result、`kind`、ブランドはどの形でも使う。形を変えるのは今の形で業務を支えられなくなったときで、transaction script → active record → domain model と進め、event sourcing へは状態ベースの集約を経由する
- 使わない: `map`・`andThen`・`pipe`・do 記法などの合成子、`ResultAsync`、`Option`、`unwrap`、Effect、DI コンテナ、ORM

## 型で業務を表す

- 判別子は `kind` だけ、値は PascalCase。イベントは過去形、コマンドは命令形、エラーは起きたこと（`CustomerNotFound`）。`kind` を業務の属性の名前に使わない
- 外部が決めた形式はそのまま受けて境界で `kind` に訳す。公開する形式は `kind` にそろえる
- 一覧は `as const` の配列から型を作る。`type` で書き、`class`・`interface`・`enum`・`namespace` を使わない（フレームワークが class を求める所を除く）。関数のフィールドはプロパティ記法
- 意味の違うプリミティブ（ID、金額、数量、時刻）は `Brand<T, "型名">` にし、型と同じ名前のオブジェクトの `parse`（`Quantity.parse`）だけが作る。`as` は `parse` の中だけで、直前に `// biome-ignore lint/plugin: <理由>` を書く
- `parse` は throw せず `Result<ブランド型, エラー>` を返す。エラーの文脈は型付きのフィールド（`min`、`max`）で持つ。自分たちで生成した値も `parse` を通し、`Result.expect` で受ける
- 状態ごとに型を分け、その状態でだけ意味のあるフィールドを持たせる。`boolean` のフラグや省略可能なフィールドで状態を表さない。遷移関数は遷移元の型だけを受け、遷移先の型を返す。状態が分からない所は `switch` で分け、遷移できない状態はエラーで返す
- 1 トランザクションで変える集約は 1 つ。ほかの集約は ID で参照する。集約は `version` で楽観ロックをかけ、競合はワークフローが扱うなら Result、扱わないなら例外
- 省略は `T | undefined`。配列は `readonly T[]`。1 つ以上が業務のルールなら `NonEmptyArray<T>`（`isNonEmpty`、`mapNonEmpty`）
- イベントはワークフローの戻り値で返し、ドメインから publish しない。内部と公開用は別の型にする。業務の結果ごとに 1 つにし、項目の変更ごとに作らない。適用した値（税率、料率、為替）を入れる
- 個人情報は zod で受けた直後に `Sensitive<T>` で包み（`.transform(Sensitive.of)`）、要る所でだけ `reveal()` する。ログ、エラー、AI へのプロンプトには包んだまま渡す

## 日本の業務データ

`packages/fp` ではなく共有の核のパッケージに置く。

- 円だけなら `Yen = Brand<number, "Yen">`（安全な整数）、複数の通貨なら `amount: bigint` と通貨。`* 1.1`・`toFixed`・`Math.round` を使わず、整数の商と余りで丸める
- 消費税は 1 枚の請求書につき税率ごとに 1 回だけ丸める（¥105 × 3 行・税抜 10%・切り捨てなら 31 円。行ごとの 30 円は誤り）。丸め方と税抜・税込は設定に持ち、適用した税率と税額を行とイベントに保存する。合計を分けるときは最大剰余の方法で 1 円のずれを無くす
- 時刻は `Instant`（epoch ミリ秒）、`CalendarDate`（日本時間の暦日）、`BusinessDate`（営業日。書き込むときに決めて保存する）に分ける。日本時間は固定の +9 時間で 1 つの部品で変換し、`toISOString().slice(0, 10)` と D1 の `'localtime'` を使わない。営業日は `[切り替え時刻, +24 時間)`
- Temporal は、Workers とブラウザの対応を公式のドキュメントで確かめるまで使わない。祝日は内閣府の CSV からビルドで作り、データの終わりより先は例外にする
- 氏名と会社名は入力のまま保存する。NFKC は番号・数字・カナと検索のキー（別の列）にだけ掛ける。部分一致は `instr(key, ?) > 0`（D1 の `LIKE` は長さの上限で失敗する。今の上限は公式のドキュメントで確かめる）、大きな表は FTS5 の trigram で、3 文字未満の語は走査にする。文字数は code point で数える
- 電話番号は書かれたまま保存し、数字だけで照合する。法人番号は検査用の数字を確かめる

## 失敗の扱い

| 分類 | 表し方 |
| --- | --- |
| ドメインのエラー（在庫切れ、遷移できない状態） | ユースケースごとの共用体を `Result` で |
| 回復の手順が業務で決まっている外部の障害 | 名前を付けた種類で `Result` に |
| 想定外のインフラの障害 | 例外（reject）のまま最上位の境界へ |
| 契約の違反、データの破損 | `assertNever`、`Result.expect` で例外 |

- 迷ったら「呼び出し側が種類ごとに違う行動をとるか」で決める（とるなら Result）。業務の正常な結果（該当なし、スキップ）は成功側の共用体で返す
- 合成は `await` と早期 return（`if (r.kind === "Err") return r;`）。Result を返す関数は戻り値の型を書く。最初の Err で止めるなら `Result.all`、全部集める（入力フォーム）なら `Result.collect`。非同期は先に `Promise.all` で待ってから渡す
- エラーはユースケースごとの共用体にし、共通の `AppError` を作らない。大きくなりすぎたら操作を分ける。文脈は型付きのフィールドで持ち、文言は出口で作る。`cause: unknown` を入れない
- 下位のエラーは、呼び出し側が区別するならそのまま足し、意味が変わるなら新しい種類で包む
- 例外を Result にするのは `Result.try` / `tryAsync`（関数を渡す）だけ。写すのは業務として扱う例外だけで、ほかは投げ直す
- 想定外の例外は途中で捕まえず、入口ごとに最上位の境界を 1 か所置く
  - HTTP・MCP: 内部の情報を含まない 500 相当
  - キューの consumer: 投げ直すか `retry()`。正常に返すと batch は処理済みになる。`ack()` は書き込みの成功の後
  - Workflow のステップ: 投げ直し、再試行は Workflows に任せる
  - cron: 投げ直す。再試行されるかは公式のドキュメントか実測で確かめてから決める
- `Result.expect` は、自分たちが書いた DB の行・生成した値・定数をドメインの型に戻すときだけ。フレームワークが例外を求める所（Workflow の再試行、`transactionSync` の巻き戻し）では、境界で例外に変えて理由をコメントに書く
- 出口（HTTP、MCP、キュー）ごとに、内部のエラーを公開用のコードとステータスへ写す網羅的な `switch` を 1 か所に置く。`default` は `return assertNever(x)` だけ。ユースケースにステータスや文言を持たせない
- 公開用のコードは内部の `kind` と別の言葉にする。存在を漏らしたくないなら「見えない」と「存在しない」を同じコードにする。クライアントと共有する一覧は `as const` の配列にし、知らないコードは汎用の表示と再読み込みの案内にする

## ワークフローと依存

- 公開する関数の型を先に書き、依存は出さない。実装は `makeXxx = (deps: XxxDeps): Xxx => async (command) => …` の 2 段
- 入力は 1 つのコマンドにする。同じ型の引数を並べず、名前のないタプルを返さない。「どうやるか」を渡す引数（`skipValidation`、`mode`）を作らず、関数を分ける
- 読む → 判断する（純粋）→ 書く の順。判断は `decideXxx(state, command, context)` が `Result<{ 新しい状態; イベント }, エラー>` を返し、保存も通知もしない。保存の仕方が変わる結果は共用体の値で返す。I/O だけの層に分岐を置かない
- ドメインとユースケースで `Date.now()`・`new Date()`・`Math.random()`・`crypto.randomUUID()` を呼ばない。`now` と `newXxxId` をポートで受け、判断には `context` の値で渡す
- ポートは I/O の操作 1 つに 1 つの関数の型（`FindCustomer = (id: CustomerId) => Promise<Customer | undefined>`）。使う側が業務の言葉で宣言し、実装から型を作らない。判断に要る分だけを返す。多数のメソッドの Repository を作らない
- 書き込みのポートは `Promise<void>` で、失敗は reject。分岐すべき結果（一意制約の違反を「登録済み」とする）があるときだけ共用体を返す
- 組み立ては入口ごとに 1 か所（`createDeps(env, overrides)`）。環境変数を読むのはここだけで、Workers ではリクエストごとに組み立てる。複数の入口が使う組み立ては 1 つのモジュールにする。時刻・ID・外部への `fetch` を差し替えられるようにする。下位だけが使う設定値は組み立てで焼き込む
- Secrets Store の秘密の値は `await env.X.get()` でしか読めない。入口（fetch・queue・scheduled・DO の fetch と alarm）で文字列にして検証してから組み立てに渡し、下位に binding を渡さない。isolate ごとに短い時間（例: 1 分）だけ覚え、読みかけの Promise はリクエストをまたいで共有しない。プレビューの平文の secret も同じ関数で文字列にする
- トランザクションはアダプタに閉じる。D1 は `batch` で 1 回にし、不変条件は 1 文の SQL の条件で守る。確実に届けるイベントは状態と同じ `batch` で outbox に書き、受け手はイベントの ID で重複を除く。2 相コミットを使わず saga で戻し、saga に業務の分岐が出たら process manager にする
- テナントごとの違いは、変わり目ごとの関数の型と種類にし、`Record<種類, 関数>` を組み立てに置く。設定には種類を保存して `parse` し、ユースケースはテナントで分岐しない

## 境界（入力・出力・永続化）

| 段階 | 担当 | 確かめること | 失敗 |
| --- | --- | --- | --- |
| `unknown` → DTO | zod を `parseWith` で | 形と上限（長さ、件数） | 400。項目だけを返し、入力値は返さない |
| DTO → ドメイン | ドメインの `parse` | 業務の制約 | ユースケースのエラーとして 422 |

- zod はドメインに入れない。同じ制約を両方に書かない。正規表現や 1 文字ずつ見る `parse` は先頭で長さを確かめる。zod は正規化の後に上限を置く
- `JSON.parse(...) as X` を書かない。HTTP の本文、Webhook、外部 API の応答、DB の JSON 列、キュー、WebSocket、LocalStorage は `parseWith`（同期のスキーマだけ）を通す
- DTO → ドメインは Result、ドメイン → DTO は必ず成功する関数にし、アダプタの側に置く。ドメインの型を直接 `JSON.stringify` しない
- DB: ORM を使わず SQL を D1 の API で実行し、値は `?` と `.bind()`。列を明示する。`all<T>()` で型を付けず、行は `packages/db` の列を読む関数とドメインの `parse` で型にする（zod は使わない）。DB の値（`"placed"`）と `kind`（`"Placed"`）は変換関数で写し、ドメインから行への変換も状態ごとに 1 か所にする
- 行の変換の失敗は破損として `Result.expect` で例外にする。過去の版の形は破損ではなく受け付ける
- 読み取り専用の画面には、ドメインを通さない専用の型を作ってよい。閉じた列挙は DB の CHECK と `oneOf` に同じ一覧を渡す
- 外部 API の失敗は回復の手順ごとの共用体にし、応答の本文も `parseWith` で検証する。タイムアウトは「結果不明」という別の種類にし、自動の再試行は冪等な呼び出しだけ。再試行の判断は純粋関数にする。クライアントの型は訳してからドメインに渡す。両端が同じ手順を知るもの（署名の検証、冪等キー、直列化、CSV の文字コード）は 1 か所に置く
- フロントエンドは応答を受けた直後に `parseWith` で Result にし、スキーマは寛容にする（`z.strictObject` にせず、知らない `kind` に逃げ道を置く）。例外を前提にしたライブラリとは 1 か所でつなぐ。取得の状態は `Loading | Failed | Loaded` の共用体にする

## 自前の部品

各リポジトリに `packages/fp`（例: `@app/fp`）を置く。依存は 0 で、公開しない。

| ファイル | 中身 | 使いどころ |
| --- | --- | --- |
| `result.ts` | `Result`（`kind` のプレーンなオブジェクト）、`ok`、`err`、`Result.try`・`tryAsync`・`all`・`collect`・`expect` | どこでも |
| `brand.ts` | `Brand<T, Name>` | 値の型 |
| `non-empty.ts` | `NonEmptyArray`、`isNonEmpty`、`mapNonEmpty` | 1 つ以上の配列 |
| `assert-never.ts` | `assertNever`（値を文字列にしない） | `switch` の `default` |
| `sensitive.ts` | `Sensitive.of`、`reveal()`（直列化で `[REDACTED]`） | 個人情報 |
| `schema.ts` | `parseWith`（Standard Schema の型を写して持つ。issue に入力値を入れない） | 境界だけ。入口を `@app/fp/schema` に分ける |

- `packages/db` に列を読む関数（`text`、`integer`、`nullable`、`oneOf`、`textWith(parse)`、`integerWith(parse)`）を置き、アダプタから使う
- 部品を足すのは、同じ手書きが 3 か所以上に出てから。値の形（プレーンなオブジェクト）は変えない

## 依存の向きと機械による検査

| 層 | import してよい | してはいけない |
| --- | --- | --- |
| ドメイン | `@app/fp`、共有の核 | `@app/fp/schema`、zod、アダプタ、外部のパッケージ |
| ユースケース | ドメイン、`@app/fp` | インフラの実装（型も）、zod |
| 境界とアダプタ | 上に加えて `@app/fp/schema`、zod、`packages/db` | 環境変数 |
| 組み立て | すべて | — |

- 依存の向きは dependency-cruiser などで検査する
- tsconfig は `strict`・`noUncheckedIndexedAccess`・`exactOptionalPropertyTypes`・`noImplicitReturns`・`noFallthroughCasesInSwitch`・`noPropertyAccessFromIndexSignature`・`noUnusedLocals`・`noUnusedParameters`・`verbatimModuleSyntax`・`erasableSyntaxOnly`・`isolatedModules`。ドメインのパッケージは `"types": []`
- Biome のプラグイン: コード全体で `as`（`as const` を除く）と、SQL への値の埋め込みを禁じる。ドメインとユースケースだけで `class`・`throw`・時刻と乱数の生成を禁じる。`noExplicitAny`・`noNonNullAssertion`・`noParameterAssign` を error にする。抑止は `// biome-ignore lint/plugin: <理由>` だけ
- 規則と依存の検査を足すときは、わざと違反を置いて発火を確かめる

## 計画に書くこと

- 計画の README の「決めたこと」: 今のリポジトリの形に合わせてこの決まりから外れた所と理由
- 「変更するファイル」: 層（ドメイン、ユースケース、アダプタ、入口、組み立て）が分かるように並べる
- 「従う決まり」: この文書の決まりのうち、そのフェーズが触れて、リポジトリの CLAUDE.md に無いものを、今のリポジトリの名前で写す。既存の形に合わせたフェーズでは、手本にする既存のファイルを名指しする
- 「約束」: フェーズの外が使う型・関数・ポートの名前と型、フェーズの外や API に出る `kind` の値とエラーの共用体の種類、出口の変換表（`kind` → ステータスとコード）、外部入力の上限の値（zod とブランドの `parse`）、表の列と状態ごとに埋める列
- 「作り方」: Result と例外の振り分け、同じ `batch` で書くもの。内部の型、`context` の渡し方、組み立ての細部はワーカーが既存の形に合わせて決める
- 「完了の条件」: 規則を足すフェーズでは、違反を置いて発火を確かめるコマンドと期待する出力
- 機能の計画では CLAUDE.md を変えない

## CLAUDE.md に足す候補

計画のスキルが最後の報告に並べる。足すかは利用者が別に決める。

- 判別子は `kind`、値は PascalCase。`class`・`interface`・`enum`・`namespace` を使わない（フレームワークが求める所を除く）
- 意味のあるプリミティブは `Brand` を付け、`<型名>.parse` だけが作る。`as` は `as const` 以外禁止
- 想定内の失敗は `Result`、想定外は throw のまま入口の最上位で捕まえる。合成は `await` と早期 return。エラーはユースケースごとの共用体。`default` は `assertNever` だけ
- 判断は純粋関数。時刻・ID・乱数は引数で受ける。依存は関数の型で宣言し `makeXxx(deps)` で受ける
- 外部入力は `parseWith` とドメインの `parse` を通す。出口ごとに 1 か所の網羅的な変換。個人情報は `Sensitive`
- DB は SQL と `.bind()`。`all<T>()` で型を付けず、列を読む関数と `parse` で型にする

## 依頼主に確かめること

- 業務として扱い方が決まっている失敗（外部のサービスが止まったら手で確かめる、など）と、画面の導線
- 「該当なし」「スキップ」が正常な結果か。1 つ以上あることが業務のルールか
- 存在を知られてはいけないもの
- 消費税の丸め方と税抜・税込、通貨が円だけか、営業日の切り替え時刻
